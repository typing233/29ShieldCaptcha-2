## 请求处理流程

```
1. 客户端请求 GET /api/challenge
   → 动态难度计算（基于当前负载）
   → 返回 Challenge{id, nonce, difficulty, signature}

2. 客户端本地：
   → WebWorker 求解 PoW
   → 采集行为数据（鼠标/触摸轨迹、加速度、停顿）
   → 采集设备指纹（Canvas, WebGL, Audio, 硬件特征）
   → 用户完成滑块拖动

3. 客户端提交 POST /api/verify
   → 速率限制检查（Redis 滑动窗口 / 内存令牌桶）
   → HMAC 签名验证（防篡改）
   → 有效期检查
   → PoW 解答验证
   → 交互行为验证（时长、轨迹点数、移动检测）
   → [可选] 风险评分引擎：
     a. 行为分析（速度方差、加速度平滑度、曲率、停顿分布）
     b. 重放检测（DTW 轨迹相似度 vs Redis 缓存）
     c. 信誉评分（IP 失败率、指纹-IP 映射异常）
     d. 规则引擎（热加载条件匹配）
   → Nonce 标记已用（防重放）
   → 异步写入验证日志（PostgreSQL）
   → 返回结果 + 风险评分 + 命中原因
```

## 核心组件

### 风险评分流水线

```go
type Scorer interface {
    Name() string
    Score(ctx, req) → (score 0.0-1.0, confidence, reasons[])
    Weight() float64
}
```

评分器并行执行，加权聚合最终分数：
- `finalScore = Σ(score_i × weight_i) / Σ(weight_i)`
- 0.0-0.4 → Pass
- 0.4-0.6 → Review（通过但标记审查）
- 0.6-0.8 → Escalate（下次提高难度）
- 0.8-1.0 → Block

### 降级与熔断

```
Redis 熔断器：
  连续 5 次失败 → 打开（不再尝试）
  10 秒后 → 半开（尝试 1 次 ping）
  成功 → 关闭（恢复正常）
  
降级行为：
  Redis 不可用 → 自动回退到内存存储（宽松限速）
  PostgreSQL 不可用 → 跳过日志写入和规则加载
```

### 规则热更新

```
1. 管理员通过 Admin API 更新规则 → PostgreSQL
2. 触发立即重新加载（API handler 直接调用 Reload()）
3. 后台轮询每 30 秒检查 updated_at 变化
4. 使用 atomic.Value 原子交换规则集（无锁读取）
```

### 多维度速率限制

```
维度：IP / 设备指纹 / 组合
存储：Redis Sorted Set（滑动窗口）
自适应：
  - 正常：base_rate / 分钟
  - 被标记后：base_rate / 4 / 分钟（持续 5-10 分钟）
  - 连续 10 次通过后恢复
```

## 数据模型

### verification_logs
记录每次验证尝试，包含行为数据和风险评分。用于：
- 管理面板日志查询
- 信誉评分历史
- A/B 实验结果分析
- 误杀回溯

### risk_rules
条件-动作规则，支持 JSON DSL：
```json
{
  "and": [
    {"field": "risk_score", "op": ">", "value": 0.7},
    {"field": "velocity_variance", "op": "<", "value": 10}
  ]
}
```

### experiments
A/B 实验配置，通过 traffic_pct 控制流量分割。

## 安全设计

- HMAC 签名防止 Challenge 篡改
- Nonce 一次性使用防止重放
- PoW 增加批量攻击成本
- 设备指纹隐私保护（仅传输 SHA-256 哈希）
- JWT 认证 + RBAC 权限管理
- 审计日志记录所有管理操作
- bcrypt 密码哈希
